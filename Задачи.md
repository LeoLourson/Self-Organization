# Протокол: выбор лучшего организатора в группе одинаковых агентов

Файл меняет только человек. Общее описание проекта — в [README.md](README.md).

## Вопрос

По каким наблюдениям за действиями других агентов группа одинаковых агентов
находит лучшего руководителя. Это первый шаг к более общему вопросу: какие
структуры взаимодействия складываются в группе сами (кто кому передаёт информацию
и какие роли выполняет) и какие из них лучше прогнозируют.

## Участники

Пять агентов A1–A5: одна модель, одни настройки, один системный промпт
([prompts/system.txt](prompts/system.txt)). Каждый агент помнит весь прогон.
Агенты различаются только случайностью ответов, очерёдностью ходов и тем,
что каждый успел увидеть.

## Задача

Прогноз P-индекса — недельного числа протестных событий во Франции.
Источник — дневные файлы событий [GDELT 1.0](https://www.gdeltproject.org/data.html):
события с корневым кодом CAMEO 14 («протест») и местом действия во Франции,
просуммированные по неделям с понедельника, 2024–2025 годы
([data/fetch_gdelt.py](data/fetch_gdelt.py)). Агенты не знают ни страну, ни даты:
недели пронумерованы с первой.

Агент видит последние 52 недели и прогнозирует следующие 4.

## Прогон

Пять раундов. Раунд $r$ (нумерация с нуля) прогнозирует недели $t_r+1,\dots,t_r+4$,
где $t_r = 52 + 4r$. Реальные значения раунда $r$ входят в историю раунда $r+1$.

1. Организатор получает ряд и даёт каждому из четырёх исполнителей по заданию.
2. Каждый исполнитель получает своё задание и ряд и отвечает организатору.
   Этот ответ видит только организатор.
3. Организатор получает все ответы и даёт прогноз на 4 недели.
4. Программа считает точность прогноза и рассылает сводку раунда всем агентам.
   Агент читает сводку в начале своего следующего сообщения.

После пятого раунда каждый агент тайно ранжирует четырёх других как организаторов
и объясняет ранжирование. О голосовании агенты заранее не знают.

**Очерёдность.** В повторе $k$ раунд $r$ организует агент $A_{((r+k)\bmod 5)+1}$.
За повторы 0–4 каждый агент организует каждый из пяти периодов по разу,
поэтому трудность периода не связана с конкретным агентом.

**Точность** — MASE: средняя абсолютная ошибка прогноза, делённая на среднюю ошибку
наивного прогноза «как на прошлой неделе» по видимой истории. MASE меньше 1 —
прогноз лучше наивного.

## Условия

Условие задаёт, что входит в сводку раунда:

| Условие | Организатор | Задания всех исполнителей | Точность организатора | Реальные значения |
|---|---|---|---|---|
| `full` | да | да | да | да |
| `score` | да | нет | да | да |
| `roles` | да | да | нет | да |
| `blind` | да | нет | нет | да |

Своё задание исполнитель знает в любом условии.

## Что измеряем

- Согласие голоса с точностью: коэффициент Кендалла $\tau$ между ранжированием
  агента и порядком тех же организаторов по MASE. $\tau=1$ — порядки совпадают,
  $\tau=-1$ — обратны. В итоге прогона — поле `vote_accuracy_tau`.
- Согласие голосующих между собой.
- Граф «организатор → исполнитель» с ролями: после прогонов задания размечаются
  по словарю ролей. Смотрим, повторяются ли роли и перенимают ли агенты удачную схему.

Точность зависит от трудности периода и от номера раунда: поздние организаторы
видели больше. В анализе обе переменные входят как факторы.

## Способы запуска агентов

- API: история агента хранится программой и целиком уходит в каждый запрос.
- Субагенты Claude Code: один субагент на агента на весь прогон, новые сообщения
  дописываются в его разговор. На время прогонов личные инструкции и навыки
  Claude Code убираются командой `python run.py sandbox on`. Встроенный системный
  промпт Claude Code остаётся, и его содержимое не записывается. Поэтому одна и та
  же модель через API и через субагентов — два разных условия.
