# Протокол: выбор лучшего организатора в пуле одинаковых агентов

Файл меняет только человек.

## Вопрос

По каким наблюдениям за действиями других агентов пул одинаковых агентов
выявляет лучшего «руководителя». Это первый шаг к общей задаче: какие структуры
взаимодействия (граф передачи информации и распределение ролей) самоорганизуются
в пуле и какие из них лучше прогнозируют.

## Участники

5 агентов A1–A5: одна модель, одни настройки, один системный промпт
(`prompts/system.txt`). У каждого агента постоянная история на весь прогон.
Агенты различаются только стохастикой ответов, очерёдностью и накопленной историей.

## Задача

Прогноз недельного P-индекса — числа протестных событий в одной стране
(`data/series.csv`). Страна и даты скрыты, недели пронумерованы. Горизонт
`horizon` = 4 недели, агенты видят последние `history_weeks` = 52 недели.

## Прогон

5 раундов. Точка прогноза раунда $r$ (с нуля) — неделя
$t_r = \text{first\_origin} + r\cdot\text{horizon}$, так что факт раунда $r$
входит в историю раунда $r+1$.

1. Организатор получает ряд и раздаёт каждому из 4 исполнителей по задаче (JSON).
2. Каждый исполнитель получает свою задачу и ряд и отвечает организатору. Ответ
   видит только организатор.
3. Организатор получает все ответы и даёт прогноз на 4 недели (JSON).
4. Среда считает MASE прогноза (ошибка, делённая на ошибку прогноза «как на прошлой
   неделе» по видимой истории) и кладёт итоги раунда во входящие всех агентов.
   Итоги приходят агенту в начале его следующего сообщения.

После 5 раундов каждый агент анонимно ранжирует четырёх других как организаторов
и обосновывает ранжирование. О голосовании агенты заранее не знают.

Очерёдность организаторов — циклический латинский квадрат: в повторе $k$ раунд $r$
организует агент $A_{((r+k)\bmod 5)+1}$. За повторы 0–4 каждый агент организует
каждый период.

## Условия: что входит в итоги раунда

| Условие | Организатор | Задания всем исполнителям | MASE организатора | Реальные значения |
|---|---|---|---|---|
| `full` | да | да | да | да |
| `score` | да | нет | да | да |
| `roles` | да | да | нет | да |
| `blind` | да | нет | нет | да |

Свою задачу исполнитель знает в любом условии. Соответствие исходному замыслу:
`full` — пункт 3, `score` — пункт 5, `blind` — пункт 6; `roles` добавлено.

## Что измеряем

- Согласие голоса с точностью: Kendall $\tau$ между ранжированием агента и порядком
  тех же организаторов по MASE (`vote_accuracy_tau` в результате).
- Согласие голосующих между собой.
- Граф «организатор → исполнитель» с метками ролей: задания кодируются по словарю
  ролей после прогонов; смотрим, повторяются ли роли и копируют ли агенты
  удачную схему.

Точность зависит от трудности периода и от позиции раунда: поздние организаторы
видели больше. В анализе обе переменные входят как факторы.

## Транспорты

- `api`: история агента хранится средой и целиком уходит в каждый запрос.
- `subagent`: агент — один субагент Claude Code на весь прогон, сообщения
  дописываются в его контекст через SendMessage. На время прогонов пользовательские
  инструкции Claude Code убираются (`run.py sandbox on`). Встроенный системный
  промпт Claude Code остаётся, его точный состав не логируется; сравнение
  одной модели через оба транспорта — отдельный фактор.
