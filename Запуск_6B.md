# Запуск эксперимента на локальной модели 6B

Локальная маленькая модель даёт две вещи: повторы практически бесплатны и у неё
видны логиты — вероятности, с которыми модель выбирала каждое число в прогнозе
организатора. По логитам видно, в каких числах группа была единодушна, а в каких
расходилась: это прямой сигнал для вопросов о конвенциях и коллективной памяти
([Задачи.md](Задачи.md), «Что измеряем»).

## 1. Что понадобится

- Python 3.11+ и `python -m pip install -r requirements.txt` (нужен только `openai`).
- Локальный сервер с OpenAI-совместимым API и инструкция-модель около 6B параметров.
  6B в сжатии Q4 занимает 4–5 ГБ памяти, без сжатия — около 12 ГБ.
- Контекст сервера — по возможности от 32k токенов: к пятому раунду история агента
  вырастает примерно до 20–30 тысяч токенов. Если у модели контекст меньше,
  уменьшите `history_weeks` или `worker_words` в config.json — но учтите, это
  изменение протокола, прежние прогоны после него не продолжаются.
- Для русскоязычного эксперимента удобнее русскоязычная модель, например
  `yandex/YandexGPT5-Lite-6B` или её дообучения. Подойдёт любая instruct-модель
  близкого размера: «какая модель» здесь само по себе часть вопроса
  (направление 12.12 обзора — модель, оболочка и положение в сети).

## 2. Поднять сервер

Движок `local` уже описан в config.json: адрес по умолчанию
`http://localhost:11434/v1` (порт Ollama), свой адрес передаётся переменной
окружения `LOCAL_BASE_URL` — конфиг править не нужно.

**vLLM** (Linux/WSL, отдаёт логиты):

```bash
pip install vllm
vllm serve yandex/YandexGPT5-Lite-6B     # адрес http://localhost:8000/v1
export LOCAL_BASE_URL=http://localhost:8000/v1
```

**LM Studio** (графический интерфейс, Windows): найдите в поиске модель ~6B
(например, YandexGPT 5 Lite 6B в GGUF), во вкладке Developer запустите локальный
сервер и задайте `LOCAL_BASE_URL=http://localhost:1234/v1`. Точное имя модели
показано рядом с сервером.

**llama.cpp**: `llama-server -m модель-Q4_K_M.gguf --port 8080 -c 32768`,
затем `LOCAL_BASE_URL=http://localhost:8080/v1`. Логиты отдаёт.

**Ollama**: `ollama pull <модель>` — адрес по умолчанию уже в config.json.
Ollama не отдаёт логиты для chat-запросов: если нужны логиты, возьмите vLLM,
LM Studio или llama.cpp.

Проверка связи (имя модели в ответе должно совпадать с `profiles.local_6b.model`
в config.json; при несовпадении впишите точное имя из ответа):

```bash
curl -s "$LOCAL_BASE_URL/chat/completions" -H "Content-Type: application/json" \
  -d '{"model": "yandex/YandexGPT5-Lite-6B", "messages": [{"role": "user", "content": "привет"}], "max_tokens": 20}'
```

## 3. Настройка прогона

Профиль уже в config.json:

```json
"local_6b": {
  "transport": "api", "engine": "local", "model": "yandex/YandexGPT5-Lite-6B",
  "settings": {"temperature": 0.5, "max_tokens": 2000, "logprobs": true, "top_logprobs": 5}
}
```

- `temperature: 0.5` — компромисс: ниже — надёжнее JSON, выше — заметнее различия
  между одинаковыми агентами, на которых держится самоорганизация.
- `max_tokens: 2000` перекрывает общий `api.max_tokens` (16000): локальные серверы
  часто не дают столько на один ответ.
- `logprobs` и `top_logprobs` включают сохранение логитов чисел прогноза. Если
  сервер не поддерживает их и отвечает ошибкой — уберите эти два параметра,
  просто не появится поле `forecast_confidence`.
- Судья по умолчанию ходит через облачный API (`judge_profile: deepseek_pro`).
  Для полностью локального прогона поменяйте в config.json `judge_profile` на
  `local_6b`: судья тоже станет локальным. Это меняет ID прогонов (судья входит
  в их описание), но не меняет протокол для агентов.

## 4. Запуск

Команды те же, что и для облачных профилей:

```bash
python run.py plan --profile local_6b --repeats 5             # список прогонов серии
python run.py start --profile local_6b --condition open --repeat 0
python run.py advance --id <ID>                               # идёт до конца прогона
python run.py status --id <ID>
```

Один прогон — 40 шагов агентов и 25 запросов судье. На видеокарте это десятки
минут, на процессоре — часы. Ответы кэшируются в `requests.sqlite3`: прерванный
`advance` продолжается с места обрыва и ничего не пересчитывает. Остановка —
файл `STOP` в корне проекта. Повторы 0–4 закрывают латинский квадрат
(`python run.py plan` показывает, какие прогоны серии уже готовы).

Маленькая модель чаще ломает формат JSON — среда переспросит до трёх раз, после
чего прогон получит статус `failed` и всё равно запишет частичный результат.
Если `failed` стал нормой: снизьте `temperature`, проверьте контекст сервера
или возьмите модель получше в следовании формату.

## 5. Что смотреть в результате

В `runs/results/<ID>.json`, помимо прежних полей:

- `observables.role_matrix` — назначенные роли: кто какую роль получал;
- `observables.specialization` — фактическая специализация: доля назначений
  агента, пришедшихся на его самую частую роль (1 — вся работа в одной роли);
- `observables.links` — сеть «организатор → исполнитель»: кто кому сколько раз
  передавал задания;
- `observables.conventions` — по раундам, доля назначений «исполнитель → роль»,
  уже встречавшихся раньше. Рост доли в `open` при отсутствии роста в `closed` —
  признак конвенции, передаваемой через сводки, а не случайного притяжения;
- в каждом раунде `forecast_confidence` — средняя уверенность организатора
  (средний logprob ответа) и альтернативы по числам прогноза. Сравнивайте числа
  между агентами и раундами: сближение распределений говорит о складывающейся
  общей памяти, устойчивое расхождение — о независимых подходах.

Между условиями `open` и `closed` и повторами 0–4 всё это сравнивается напрямую:
прогоны одной серии отличаются только повтором и условием.
