# Запуск эксперимента на локальной модели

Локальная модель делает серию повторов практически бесплатной, а локальный
сервер отдаёт логпробы: логарифмы вероятностей токенов. По логпробам чисел
прогноза видно, в каких числах организатор был уверен, а в каких расходился
(поле `forecast_confidence`, раздел 5).

## 1. Что понадобится

- Python 3.11+ и `python -m pip install -r requirements.txt` (нужен только `openai`).
- Локальный сервер с OpenAI-совместимым API и инструкция-модель 6–8B.
  Открытая русскоязычная модель — YandexGPT 5 Lite 8B: в сжатии Q4_K_M она
  занимает около 5 ГБ памяти и идёт на процессоре, видеокарта не нужна.
- Контекст сервера — по возможности от 32k токенов: к пятому раунду история
  агента вырастает примерно до 20–30 тысяч токенов. Если у модели контекст
  меньше, уменьшите `history_weeks` или `worker_words` в config.json — но учтите,
  это изменение протокола, прежние прогоны после него не продолжаются.
- У YandexGPT 5 Lite в шаблоне нет роли system: инструкции среды передаются
  первой репликой «Пользователь». На облачных профилях они идут отдельным
  системным сообщением, поэтому прогон на этой модели — отдельное условие,
  а не продолжение облачных.

## 2. Поднять сервер

### Ollama

```bash
ollama pull hf.co/yandex/YandexGPT-5-Lite-8B-instruct-GGUF:Q4_K_M
```

Шаблон, который Ollama берёт из GGUF-файла, теряет system и переставляет реплики,
а у самой модели формат диалога свой:

```
<s> Пользователь: …\n\n
    Ассистент: …\n\n
    Пользователь: …\n\n
    Ассистент:[SEP] <ответ>
```

Поэтому модель собирают заново с шаблоном из карточки модели. Файл `Modelfile`:

```
FROM hf.co/yandex/YandexGPT-5-Lite-8B-instruct-GGUF:Q4_K_M
TEMPLATE """<s>{{ if .System }} Пользователь: {{ .System }}

{{ end }}{{ range .Messages }}{{ if eq .Role "user" }} Пользователь: {{ .Content }}

{{ else if eq .Role "assistant" }} Ассистент: {{ .Content }}

{{ end }}{{ end }} Ассистент:[SEP]"""
PARAMETER stop <s>
PARAMETER stop [SEP]
PARAMETER stop </s>
PARAMETER temperature 0.5
PARAMETER num_ctx 32768
```

```bash
ollama create yandex-gpt-5-lite-8b -f Modelfile
```

Шаблон склеивает системное сообщение с первой репликой пользователя: без этого
агенты не увидели бы правила эксперимента. Проверка связи — имя модели в ответе
должно совпадать с `profiles.local_yandex.model` в config.json:

```bash
curl -s http://localhost:11434/v1/chat/completions -H "Content-Type: application/json" \
  -d '{"model": "yandex-gpt-5-lite-8b", "messages": [{"role": "user", "content": "привет"}],
       "max_tokens": 20, "logprobs": true, "top_logprobs": 5}'
```

### Другие серверы

- **vLLM** (Linux/WSL): `vllm serve <модель> --port 8000`, затем
  `LOCAL_BASE_URL=http://localhost:8000/v1`. Сервер применит шаблон токенизатора,
  а в нём роли system нет — системные сообщения до модели не дойдут; шаблон
  нужно повторить, как в Modelfile выше.
- **LM Studio** (Windows): найдите GGUF-модель, во вкладке Developer запустите
  сервер, `LOCAL_BASE_URL=http://localhost:1234/v1`.
- **llama.cpp**: `llama-server -m модель-Q4_K_M.gguf --port 8080 -c 32768`,
  затем `LOCAL_BASE_URL=http://localhost:8080/v1`. Логпробы отдаёт.

## 3. Настройка прогона

Профиль в config.json:

```json
"local_yandex": {
  "transport": "api", "engine": "local", "model": "yandex-gpt-5-lite-8b",
  "settings": {"temperature": 0.5, "max_tokens": 2000, "logprobs": true, "top_logprobs": 5}
}
```

- `temperature: 0.5` — компромисс: ниже — надёжнее JSON, выше — заметнее различия
  между одинаковыми агентами, на которых держится самоорганизация.
- `max_tokens: 2000` перекрывает общий `api.max_tokens` (16000): локальные серверы
  часто не дают столько на один ответ.
- `logprobs` и `top_logprobs` включают сохранение логпробов чисел прогноза.
  Если сервер не поддерживает их и отвечает ошибкой — уберите эти два параметра,
  просто не появится поле `forecast_confidence`.
- Судья по умолчанию ходит через облачный API (`judge_profile: deepseek_pro`).
  Для полностью локального прогона поменяйте в config.json `judge_profile` на
  `local_yandex`: судья тоже станет локальным. Это меняет ID прогонов (судья входит
  в их описание), но не меняет протокол для агентов.

Две особенности YandexGPT 5 Lite, которые среда обходит сама:

- ответ начинается отдельным пробельным токеном, поэтому попарный голос
  измеряется по второму токену ответа;
- модель иногда теряет закрывающую скобку в конце JSON; недостающие скобки
  дописываются при разборе, ответ при этом не теряется.

## 4. Запуск

Команды те же, что и для облачных профилей:

```bash
python run.py plan --profile local_yandex --repeats 5          # список прогонов серии
python run.py start --profile local_yandex --condition open --repeat 0
python run.py advance --id <ID>                               # идёт до конца прогона
python run.py status --id <ID>
```

Один прогон — 35 сообщений агентам, 30 попарных голосов и 25 запросов судье
(в solo — 5 сообщений, без голосов и судьи). На этом процессоре прогон идёт
около 50 минут, из них больше половины — генерация. Ответы кэшируются
в `requests.sqlite3`: прерванный `advance` продолжается с места обрыва и ничего
не пересчитывает. Остановка — файл `STOP` в корне проекта. Повторы 0–4
закрывают латинский квадрат (`python run.py plan` показывает, какие прогоны
серии уже готовы).

Маленькая модель чаще ломает формат JSON — среда переспросит до трёх раз, после
чего прогон получит статус `failed` и всё равно запишет частичный результат.
Если `failed` стал нормой: снизьте `temperature`, проверьте контекст сервера
или возьмите модель получше в следовании формату.

## 5. Что смотреть в результате

В `runs/results/<ID>.json`, помимо прежних полей:

- `observables.role_matrix` — назначенные роли: кто какую роль получал;
- `observables.specialization` — фактическая специализация: доля назначений
  агента, пришедшихся на его самую частую роль (1 — вся работа в одной роли);
- `observables.links` — сеть «организатор → исполнитель»: кто кому сколько раз
  передавал задания;
- `observables.conventions` — по раундам, доля назначений «исполнитель → роль»,
  уже встречавшихся раньше. Рост доли в `open` при отсутствии роста в `closed` —
  признак конвенции, передаваемой через сводки, а не случайного притяжения;
- в каждом раунде `forecast_confidence` — средняя уверенность организатора
  (средний логпроб ответа) и альтернативы по числам прогноза. Сравнивайте числа
  между агентами и раундами: сближение распределений говорит о складывающейся
  общей памяти, устойчивое расхождение — о независимых подходах.

Между условиями `open` и `closed` и повторами 0–4 всё это сравнивается напрямую:
прогоны одной серии отличаются только повтором и условием.

Термины и их соответствие словарю обзора — в словаре README.md.
